Accessibility

A button and a preferences panel, <ds-a11y>, so each person can adapt the interface to their needs: text, colours, motion, reading. It works on this whole page: try it.

Principle

A preferences panel, not an overlay

  • ▸
    Accessible without it. The product meets WCAG 2.2 AA through its own code. The panel is never a condition of access.
  • ▸
    It adapts, it does not repair. It does not claim to fix or certify accessibility, never rewrites the page with AI and loads no third-party script.
  • ▸
    The system first. Reduced motion, more contrast, dark mode and forced colours set in the operating system apply by default; the panel overrides them only on an explicit choice.
  • ▸
    Private. Choices stay on the device (or in the user's profile when the product saves them), no cookie, no tracking. « Reset » restores the defaults.

Placement and behaviour

{{ICON:accessibility:pop}}

Button

Fixed in a bottom corner (position="left|right"), never covering a chat bubble, a bottom bar or toasts. Also reachable from the user menu and the skip links (data-a11y-open).

{{ICON:layout-grid:pop}}

Panel

A non-modal side sheet on desktop, full screen and modal on phones. Focus goes to its title on open; Esc closes it and returns focus to what opened it.

{{ICON:copy:pop}}

Persistence

localStorage on public sites (storage="local"), the user's profile in an app (storage="none" + el.prefs = …).

For developers
