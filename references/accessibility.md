# Accessibility

Two layers, never confused:
1. **The product is accessible by itself** — WCAG 2.2 AA through its own code: contrast (palette_check.py), keyboard,
   focus, labels, reflow, reduced motion. This is the work of every section (`references/components.md`, `qa.md`).
2. **A preferences panel on top** — `<ds-a11y>` (`assets/runtime/a11y.js`): each person adapts text, colours, motion
   and reading to their needs. It adapts; it does not repair.

Say this in the section and to the client. "Accessibility overlays" sold as a way to make a site compliant are widely
criticised (they break assistive technology, fix nothing in the code, and have not protected sites from complaints).
The panel must never be presented as compliance, never rewrite content with AI, never inject third-party scripts.

## The component
Ships in every design system built with this skill (core section `accessibility`, live on the page).

| Attribute | Values |
|---|---|
| `position` | `left` (default) · `right` — pick the corner nothing else uses (no chat bubble, no toasts, above a mobile bottom bar) |
| `placement` | fixed (default) · `inline` (button in the flow) · `none` (no button; any `[data-a11y-open]` opens it) |
| `storage` | `local` (localStorage `<slug>-a11y`, public sites) · `none` (the app saves: set `el.prefs = …` from the user's profile, listen to `ds-a11y:change`) |
| `theme` | `data-theme` (writes `<html data-theme>`) · `class` (`<html class="dark">`) · `none` (the page owns light/dark; the design system page uses this) |
| `help-key` | `?` lists shortcuts (default) · `off` when the page already uses `?` |
| `font-base` | folder of the Atkinson Hyperlegible files (the build copies them to `dist/fonts/`) |
| `demo` | a static panel for documentation (`prefs='{json}'`, `demo-state="focus|reset|unsupported"`) |

API: `DSA11y.open() · close() · toggle() · reset() · set({text: 150}) · prefs · element · reducedMotion()`.
Events: `ds-a11y:change {prefs, changed}`, `:open`, `:close`, `:lang` (cancelable). Keys: Alt+A (Option+A) anywhere,
`?` shortcuts, Esc closes and returns focus.

## What each option needs from the page
| Option | The page must… |
|---|---|
| Text size 100–200 % | size text in `rem` (never px), let layouts reflow: grid children `min-width: 0`, long words `overflow-wrap: anywhere`, control rows that wrap. `qa.mjs a11y` checks 200 % at 390 px. |
| Spacing, readable font, left align, measure | use the font tokens; avoid justified text; avoid fixed heights on text boxes |
| High contrast, colour-vision palettes | use the colour tokens (`--color-*`, `--chart-n`) everywhere — the build computes the high-contrast values from the brand (`tokens.contrast_tokens`) and ships checked palettes (`tokens.CVD`, generated by `cvd_palettes.py`) |
| Reduce motion | honour `html[data-a11y-motion=reduce]` as well as `prefers-reduced-motion` in JS animations (`DSA11y.reducedMotion()`); custom elements that animate take `[data-motion-host]` and receive `motion="reduce"`; Hairline figures are handled |
| Strong focus, targets, cursor, guide | nothing — but never remove focus outlines in your own CSS |
| Language | the page's languages come from `ds.config.json`; strings exist in fr, it, en (others show English in the panel) |

## The section must show
Principle (above) · a "try it" button (`data-a11y-open`) · each option with what it changes and its WCAG 2.2 criteria
(1.4.1, 1.4.3/1.4.6, 1.4.4, 1.4.8 informative, 1.4.10, 1.4.11, 1.4.12, 2.2.2, 2.3.3, 2.4.7/2.4.11/2.4.13, 2.5.8, 3.1.1) ·
placement in the product (desktop corner + user menu, phone above the bottom bar, public site) · keyboard map ·
persistence and privacy · developer API. The starter section (`assets/starter/accessibility.html`) has all of it —
rewrite its text in the source language and adapt the placement to the product.

## Placement rules by product
- **App / back office**: fixed button in the corner without a chat bubble, plus an entry in the user menu; `storage="none"`
  with the user's profile so preferences follow the person across devices.
- **Public website**: fixed button, `storage="local"`; a skip link "Accessibility (Alt+A)" after "Skip to content".
- **Mobile / PWA**: above the bottom bar (`--ds-a11y-bottom: calc(64px + env(safe-area-inset-bottom))`), full-screen sheet.
- **Emails**: no panel — accessibility comes from good HTML (`references/emails.md`).
